## Publication privacy

Operator destinations and home paths are not repository defaults. The four qualification launchers use explicit, validated session configuration; remote intake identity and isolation gates remain enforced. Lockfile provenance comments omit workstation paths without changing versions or hashes. All three fork-owned commits are sanitized; upstream commits and intentional public certificate fixtures remain unchanged. Prior application qualification is preserved for unchanged inputs; routing tests and history scans are recorded separately.

## Remaining boundaries and maintenance

No full fresh production-backup restore, end-to-end S3/RabbitMQ/representative-production-scheduler/browser journey, final JS runtime image, production Compose migration or VPS rollout has been qualified. Raw native findings remain in `records/native-findings.json`, with conditional applicability and re-review requirements in `research/current-vulnerabilities.md`; no blanket suppressions or absolute clean claim are made. Plaintext API-token storage/scopes, service-secret rotation, historical data/log cleanup, backup automation, CSP, SSH/operator/monitoring and independent audit remain separate work.

Keep patch scope reviewable. On an upstream/tag/tool/lock/image change, perform intake first, reconcile the full Git delta and package entrypoints, update source-hash backport gates/notices, revalidate independent stores, repeat changed and related positive/negative controls, and assess migrations/restore/rollback before deployment. Code, database format, broker protocol, root policy and runtime compatibility can drift independently. Root distrust can break legitimate dependencies; local native backports and alternate Bun execution increase maintenance cost. Official-image provenance, dated ClamAV signatures, prebuilt binaries and unproven native call graphs remain explicit trust limits.

### Asset V2 resource authorization (local fourth review)

Alternate workspace download/check/restore/copy routes previously bypassed the project boundary already enforced by the main asset detail route. Copy and upload targets accepted unchecked entity IDs; bulk association could bind uploads to unchecked parents or apply the first asset's type to a mixed batch. `plane/utils/asset_permissions.py` now resolves source/target workspace, project and parent authority consistently before storage side effects or database writes. It also protects profile/logo mutations, draft/comment/page boundaries and legacy parent-only records. Workspace/project cover copies no longer repeat conflicting scope keyword arguments, and draft attachment copies retain their parent. Existing anonymous static-image reads and editor staging are explicitly covered. Bulk source and target validation precedes every update; database changes share one transaction.

This is a maintained fork authorization change, with no new dependency or migration. Follow future upstream changes to V2 routes, entity types, global/enterprise pages, parent permissions and frontend staging; port equivalent fixes rather than preserving duplicate implementations. Permission checks add queries and do not lock membership throughout a remote object copy. Actual object storage, production frontend workflows and other API versions remain separate qualification limits. Exact tests and artifact results belong in the existing verification record.

The shared-table review also closes token-API and legacy file siblings: generic signed downloads/completion and external-ID conflicts authorize existing assets, token uploads validate project scope, and personal user-keyed mutations cannot bypass populated workspace parents. Legacy file read/delete/restore and prospective multipart saves check every populated parent, including untyped rows. Legacy multipart uploads reject typed assets and direct callers to the MIME-checked V2 upload path. Unassociated token uploads, owner-controlled personal files and scoped legacy workspace-file compatibility remain tested; null-owner generic attachment changes require a workspace administrator. The legacy personal file list now uses a collection serializer. No dependency or migration is introduced.

Asynchronous document duplication now uses the same source/target resolver at job execution, closing the private-page reference bypass and accounting for revoked membership/changed destination authority after queueing. It skips unauthorized objects before constructing the internal SDK, validates target fields once and sanitizes destination key names. Mixed authorized objects still copy. The upstream worker fixture now attributes its issue to a real actor rather than passing a null creator as the job's user. Additional real-database controls cover private source/target, missing actor, revoked workspace/project membership, removed links, foreign scope, mixed batches and filename normalization.

Document copy jobs also authorize an active actor and destination before processing empty descriptions or contacting conversion services. Copied rows explicitly retain the actor as creator; document writes disable request-user inference to preserve original authorship and set the acting updater separately. This corrects background saves clearing attribution when no HTTP request user exists. Positive and denied empty-document controls cover conversion/persistence and unchanged author metadata.
