# Third-party provenance

Derived from makeplane/plane v1.4.3 commit `37a15d99231042b3ff5a4401fed479fdbec9effe`, retaining `LICENSE.txt` and upstream copyright. Dependencies retain their own terms/notices; record changed artifact identities in the hardening lock/intake process. Referencing an advisory/tool does not vendor or relicense it.

The workstation's first-party `tooling/python-ca-guard` supplies reusable public SPKI/trust-test context. Any copied implementation/fixture must record its source/content identity here. No private CA, production credential/database or authentication cache belongs in this fork.

`hardening/trust/fixtures` contains public certificates and source/fingerprint metadata from the existing first-party Python CA guard plus Mozilla incident2083449 (comment82,10November2026), crt.sh and eMudhra repository public chains. No incident private keys or production certificates/credentials are included. `trust_policy.py` is first-party code using Python stdlib and the runtime OpenSSL CLI; no third-party implementation is copied. The dated whole-G1/root-CS-G2 removal is an explicit conservative fork policy; it is not a claim that every such root private key was demonstrated compromised.

The Tiptap2.26.3 and deepmerge4.3.1 patches modify published source and emitted CJS/ESM/UMD entrypoints, preserving their MIT terms. Exact before/after hashes and control results are in `records/dependency-patches.json`; notices are retained under `vendored/licenses/`. Tiptap's license notice was fetched from its exactv2.26.3 upstream tag and separately screened; deepmerge's notice comes from the exact screened package payload. Source maps remain upstream and can have shifted mappings after patched emitted lines; regenerate/verify maps when adopting a new upstream build rather than hiding this mismatch.

The urllib3 pure wheel derives from the screened2.8.0 wheel SHA256`0cf3cae568d36aa9576b28dfb35f11328f1cb974ca7647d9475ebb86c75ac6e3`, preserves its bundled MIT notice, and is deterministically rebuilt as2.8.0+plane.2 (SHA256`c9907ebd38c617f89af7050fa6e26c4409410376d3ff1968787780e82e4dfce3`). CPython's pinned HTTP-response implementation is patched inside the image under its existing PSF license. Both notices are retained under `vendored/licenses/`; no claim of an upstream release or publisher signature covers fork modifications.

Its hash is bound through Debian-signed InRelease/Packages metadata verified with the qualified base's Debian archive keyring. The offline install retains Debian's copyright/license metadata in the image; the only package trigger is the inspected base ldconfig path. Archive signature verification authenticates the Debian payload, without claiming an independent rebuild.

Scanner/tool payloads and public certificate fixture provenance remain in their exact external-intake receipts; production data and credentials are excluded.
