# Security policy

## Human input

Inventory recent relevant eMudhra/SSH/compression and application vulnerabilities; review, patch and extensively test changes and related paths using established tools. VPS deployment is deferred.

## Contracts

Bind every conclusion to source/artifact identities, dependency closure, tool/runtime versions, advisory database date and test boundary. Distinguish version matches, reachable defects, mitigations/not-affected paths and incomplete checks. Suppressions require precise scope, rationale and review/expiry; no blanket package-family ignore.

Credentials, query strings, arbitrary headers, bodies and user agents must not enter general or asynchronous activity logs. Preserve upstream keyed HMAC correlation and normal HTTP behavior, cover producers/consumers/failures, and do not read streaming bodies merely to log them.

External API intake updates require an active project membership and the work item's creator, project-admin or active workspace-admin authority, preserving existing guest field restrictions. Connected-account list/detail responses omit stored access, refresh and ID tokens without deleting provider credentials needed server side. For label create/update/delete, state create/default/delete and workspace leave, role checks precede cache invalidation; denied permissions must leave both stored objects and shared cache contents untouched. Valid actions must still work and invalidate their caches. These are scoped upstream backports, not a claim that every application endpoint has been audited.

CA policy compares public keys including cross-signed forms across actual effective system and independent stores. Native negative tests require positive controls; timeouts alone are inconclusive. Scheduled issuance cutoffs differ from compromised-key distrust. No TLS bypass.

Qualify candidate artifacts before their intended execution path. Bound malformed-input tests by time/memory; use task fixtures only, never public exploit targets. SSH applicability inventory does not authorize changing host authentication.

All Bun workspace builds/types, upstream tests and actual live HTTP/PDF/realtime controls pass on their recorded unchanged-source profile; they were not repeated for the backend-only backports. Browser/storage/final-JS-image qualification remains open. Threats include anonymous/authenticated requests, cross-project access, remote assets, logged or queued secrets and supply chain. Container isolation limits impact without proving trustworthiness.

The hardened profile denies arbitrary credentialed CORS origins when no list is configured; actual-image denied/allowed-origin controls pass. Backend and shared JavaScript HTTP logs keep recognized methods, static route patterns, status/timing/outcome and necessary correlation only. The audit worker rejects old schema records, strips queued fields independently and retains the existing keyed HMAC identifier. Queued path text is accepted only when it exactly matches a configured static URL pattern; unknown/concrete URLs, queries and renamed converters become the fixed unresolved label. The registry follows Django nested include/regex route joining, is bounded to eight URL configurations, and requires a process restart when URL configuration changes. Live error wrappers do not serialize external messages, response bodies or URLs; PDF retry/controller failures omit causes. The shared exception helper emits a fixed event and bounded exception class only, without rendering the exception, cause or traceback, even in DEBUG. API viewset error branches retain fixed error codes and responses without raw exception extras; email verification failures omit cache keys and addresses. PDF rendering accepts only bounded JPEG data prepared for an authorized asset UUID, never document URL/file/object sources. Image download origins come from operator-only `PDF_ASSET_ORIGINS` (empty denies downloads), require exact HTTP(S) origin matches, omit credentials, reject redirects, abort at8seconds and bound downloaded/output bytes and decoded pixels. Strict response-framing patches cover pinned CPython3.12.16 and urllib3: hexadecimal-only chunk sizes, CRLF boundaries, a64KiB urllib3 trailer cap and no hostile chunk text in transport errors. ## Dated trust policy

`hardening/trust/policy.json` currently contains20 SPKI identities: eight compromised ECDSA intermediate keys, six November revoked RSA TLS intermediates, five eMudhra root keys and the AAA Certificate Services root key. AAA is a cross-sign issuer, not a demonstrated compromised key. Its removal is a deliberately broad root-only defense for clients that cannot consume intermediate revocations; it can also break unrelated valid chains through that root. Whole-G1 removal is a conservative fork choice stricter than browser SCTNotAfter transitions and may break legitimate existing G1 endpoints. It does not assert that all root keys were demonstrated compromised. Two RSA code-signing intermediate byte fixtures are unavailable; exact certificate fingerprints are recorded and their RootCSG2 issuer is blocked. The built backend filters and checks OS/directory/certifi/botocore/gRPC stores and removes pip/ensurepip. Public chain tests and22 native Bun TLS controls pass. Final JS service integration and every alternate custom transport remain unqualified. Never infer effective trust from merely having this file or passing the standalone tests.

## Worker logging and runtime contracts

Worker and scheduler logging replaces each handler's record before subsequent filters, queue preparation or formatting. The Python3.12+ runtime emits constant event categories, bounded logger names, valid task UUIDs and registered task names only; it never renders task arguments, return values, arbitrary extras or exception/stack objects. Celery parent, prefork-child and scheduler lifecycle hooks restore this boundary after Django logging initialization. This intentionally reduces worker error detail; task IDs and failure categories support correlation, but payloads and tracebacks must not be recovered by enabling an unrestricted handler. Later logging reconfiguration requires renewed review. API logging retains its separately minimized format. The actual-worker regression keeps default unmasked protocol1/protocol2 message representations and checks successful, failed and unregistered-task events as positive controls.

The immutable entrypoint accepts explicit api/worker/beat/manage modes and exactly the four upstream shell-command strings as aliases to reviewed argument arrays. Aliases never execute upstream shell scripts, append shell arguments or trigger automatic migrations in long-running roles. Only the migrator alias performs `manage migrate --noinput`. Custom port and worker node identity are recorded in private, atomic runtime metadata, without credentials. Health probes use that role: local API response, destination-specific broker worker ping, or a fresh scheduler-loop heartbeat with matching PID/start identity. A live management process is not proof of migration success; one-shot jobs must exit successfully. A four-second probe deadline and constant output bound health errors. Beat heartbeat proves a responsive loop, not successful delivery of every periodic task.

MinIO public signatures use `PUBLIC_S3_ENDPOINT_URL`, falling back to the explicitly configured `WEB_URL`; server/background clients use `AWS_S3_ENDPOINT_URL` or `MINIO_ENDPOINT_URL`. Request Host and scheme never select a credentialed storage endpoint. Configured custom endpoints must be absolute HTTP(S) origins without userinfo, paths, query data or fragments. URL schemes are authoritative; `MINIO_ENDPOINT_SSL` no longer overrides them. The previously used `is_server=True` constructor argument is supported. Ordinary AWS clients retain their service endpoint default. Real SDK upload/download presigning is tested without network requests; full S3 upload/recovery remains unqualified.

OAuth avatar upload/metadata and synchronous asset duplication use the configured internal storage endpoint. Synchronous and background copies publish uploaded rows only after the object copy succeeds; a storage failure returning `None` cannot create an uploaded row or replace a document's asset mapping. The endpoint returns a fixed502 response for that failure, and background copying omits only failed objects. Database creation after a successful remote copy can still leave an orphan object if the database write fails; distributed storage/database rollback is not implemented.

The pinned HTTP client's non-streaming responses have a decoded2MiB body cap, including link-preview HTML, favicons and webhook responses. The transport always streams first, bounds decoded chunks before caching Requests-compatible content, and closes the response/session on success or read/size failure. Oversized responses are not retried against every resolved address. Explicit streaming callers retain their own body budget and close obligation; OAuth avatars keep their existing upload-size cap. A decoded-byte budget does not establish a wall-clock deadline or bound every parser/native allocation. Redirect limits, IP pinning and TLS verification remain required independently.

Source snapshots, API image contexts and fixed project build helpers reject private environment files and direct or parent symlinks, including links to ignored files inside the checkout. The single explicitly reviewed locale link remains allowed only in source snapshots. Extracted image inputs must match the exact reviewed file set and hashes before the offline build starts. These checks detect staging tampering; they do not establish that arbitrary source content is trustworthy. The existing verification record owns reproductions, corrections, raw findings and exact candidate evidence.

Asset V2 signed detail/download routes, existence checks, restore, copy sources and mutations share a resource authorization resolver. Active workspace membership is required alongside active membership of the real project; legacy parent-only issue/comment/draft rows inherit their parent's project. Page assets require an active project link and membership, private-page ownership, and an owner or writer role for changes; explicitly global pages use workspace membership and role. Existing drafts remain author-only, comment changes require their author or an administrator, profile assets remain self-owned and workspace logos require workspace administrators. Public static avatars/covers/logos keep their existing anonymous read contract. This does not make private document assets public.

Upload/copy destinations resolve and validate typed UUIDs, workspace, project, existing parent and mutation authority before storage construction or row creation. Parent/project mismatches and foreign targets fail without presigning/copying. Each target's fields are populated once, including draft attachments. Editors may stage project content with an accessible project before saving its parent; upload creation also supports owner-scoped unassociated project covers/pages. Bulk association authorizes each selected source, including legacy parent-only uploads, and validates every real destination before any update, handles each entity type separately and commits database changes atomically. This adds database permission lookups and intentionally denies previously accepted unauthorized operations. Future entity types, enterprise/global-page permission overrides and changes to editor staging must extend this resolver and its positive/negative controls together. Permissions can change after a request's check; this is not a transactional authorization lock across storage and database systems or a complete audit of every asset API version/background caller.

The same resolver also guards token-API generic downloads/completion, external-ID conflict lookup, personal asset mutations and legacy session file reads/deletes/restores. Token uploads validate their actual project before presigning; unassociated token uploads remain supported. Legacy multipart serializers authorize prospective workspace/project/parent/user fields before saving files, and reject typed assets so they cannot manufacture public image types outside V2's image-upload policy. Untyped, unassociated legacy workspace files retain workspace-member reads and author/admin changes; ownerless generic attachment rows retain workspace reads and administrator changes. Personal unscoped files remain owner-only. These compatibility fallbacks do not exempt any populated project or parent reference: every stored parent is checked, even when the old row has no entity type or has several references. Legacy personal list serialization now explicitly handles multiple rows.

These checks govern current requests; they do not revoke static copies published before the fix or inspect/repair production asset history. Production data and actual storage recovery remain outside this qualification.

Asynchronous document asset copying repeats source resource/privacy checks and target authority checks using the current actor at execution time. Missing actors, revoked memberships, private sources and unauthorized destinations are skipped before SDK construction/copy or row creation. Allowed objects in a mixed batch still copy; storage success still precedes uploaded-row publication. Destination keys use the shared filename sanitizer and internal storage endpoint. This closes the route where an editable document could embed another private page's asset UUID before requesting duplication. It does not lock authorizations across remote I/O, repair older copies or authorize an unrelated task payload.

Empty-document copy jobs also check the active actor and target authority before conversion or persistence. Copied asset rows explicitly save the actor ID; document saves disable automatic request-user inference so a background job cannot clear the original author. The job records its acting updater separately.
