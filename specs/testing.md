# Testing and restricted runtime

## Human input

Review, patch and repeatedly test a maintained Plane fork, including changed and related paths, in restricted containers on the qualified Debian host. The review environment stays inert. VPS deployment and production-data testing are deferred.

## Supported boundary

`hardening/run_restricted.py` transfers the normal checkout's tracked/unignored files, rejects private environment files and unreviewed symlinks, verifies source hashes on both hosts, and mounts an immutable per-run snapshot. Application lanes require an exact built image ID. Rootless Podman uses non-root UID1000, no capabilities or privilege escalation, a readonly root, bounded CPU/memory/PIDs/time, no public ports and no home/authentication/SSH/engine mounts. Offline lanes use `network=none`; database/server/worker/role lanes use a separately inspected internal network, synthetic credentials and temporary storage. Exact task-owned cleanup preserves unrelated workloads.

`hardening/build_backend.py` builds offline from pinned Python3.12.16-slim-trixie, hash-locked binary wheels, a reproducibly patched urllib3 wheel and the verified Debian zlib security package. Source and extracted-context private-file/symlink/file-set/hash checks run before building, including parent links within the checkout and fixed non-API Dockerfile/helper inputs. No candidate package source builds, lifecycle downloads or automatic production migrations run. The qualification lane installs its own hash-pinned tool/test environment, checks dependency consistency, applies real PostgreSQL migrations and executes focused/upstream tests. The supported runtime does not contain pip/ensurepip, lxml/libxml2/libxslt or SSH executables.

## Image cleanup obligation

Qualification closeout must remove superseded backend candidates and discarded build stages by exact ID, keeping the current qualified candidate and explicitly required rollback. The builder labels images ephemeral and uses a unique build tag, but does not itself remove older images; container `--rm` and tag replacement do not provide image cleanup. Preserve logs, input manifests, security evidence and current run/deployment references. Review effective labels, ordinary/build-container references and protected ancestry under the exclusive build-retention lock, then use non-forced exact removals. Builds take the shared lock. Record removal identities, actual reclaimed space and retained exceptions in `records/verification.json`. This is an operator closeout requirement, not a newly implemented automatic image collector.

## Reproduce on this workstation

The existing external-intake receipts and dedicated session SSH agent are prerequisites. Operator routing is deliberately absent from Git. Export `PLANE_QUALIFICATION_HOST` (a reviewed SSH alias or user@hostname) and `PLANE_QUALIFICATION_ROOT` (the absolute qualification directory on that host) in the local session. JavaScript runs also require `PLANE_QUALIFICATION_INTAKE_ROOT`, the reviewed remote intake parent; dependency directories must be direct `plane-js-*` children. Missing or unsafe settings fail before remote activity. Host-key checking, batch authentication, manifest identities and container restrictions remain mandatory.

Set `PLANE_WHEELS`, `PLANE_ZLIB_DEB`, `PLANE_JS_DEPENDENCIES` and `PLANE_JS_MANIFEST` to already-screened inputs. Keep actual machine names, home paths and profiles outside version control. These commands acquire no dependencies and perform no deployment:

```sh
python3 hardening/build_backend.py \
  --wheels "$PLANE_WHEELS" \
  --manifest vendored/python-production-inputs.json \
  --zlib-deb "$PLANE_ZLIB_DEB"
python3 hardening/run_restricted.py integration --backend-image 8e0c7832768c647a5e5a7fd8e0cc907bbff312d9ef570c668622ad2f30727890
python3 hardening/run_restricted.py server --backend-image 8e0c7832768c647a5e5a7fd8e0cc907bbff312d9ef570c668622ad2f30727890
python3 hardening/run_restricted.py worker --backend-image 8e0c7832768c647a5e5a7fd8e0cc907bbff312d9ef570c668622ad2f30727890
python3 hardening/run_restricted.py roles --backend-image 8e0c7832768c647a5e5a7fd8e0cc907bbff312d9ef570c668622ad2f30727890
python3 hardening/scan_backend.py 8e0c7832768c647a5e5a7fd8e0cc907bbff312d9ef570c668622ad2f30727890
```
